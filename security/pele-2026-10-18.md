# Pele security review and Explain integration

Review date: 2026-10-18.

## Executive summary

Pele 1.6.0 is integrated as Explain's optional local renderer for standard Mermaid diagrams.
Custom SVG remains available for illustrations and precise animation.
The review finds no confirmed critical or high vulnerability in the tested runtime path.
This result is bounded by the reviewed version, test cases, and local rendering workflow.

The published artifact matches its signed metadata, verified provenance, and a reproducible source build.
The independent runtime review covers 3,093 cases.
An additional 84 hostile cases pass through the actual wrapper without a blocking finding.
The package can consume substantial resources on short input, as its security documentation anticipates.
Explain therefore uses a disposable worker, lower limits, and dimension checks.

The upstream development lockfile has a high-severity advisory chain.
Those development tools are absent from Explain's production dependency tree.
The integration's production audit reports zero known vulnerabilities at the check time.

## Scope and methods

The review uses three independent passes: supply chain, runtime injection, and resource behavior.
The source review follows the JavaScript frontend security guidance supplied with the security review skill.

Completed checks:

- Compare tarball hashes with official registry metadata.
- Verify both registry signatures and both Sigstore attestations.
- Reject deliberately tampered payloads and an incorrect workflow identity.
- Compare the release tag with the attested source commit.
- Inspect all 416 package files for unexpected content, links, and traversal paths.
- Reproduce all 413 distribution files using the locked build tools.
- Query npm, OSV, and the GitHub Advisory Database.
- Trace label escaping, CSS filtering, URL handling, and prototype protection.
- Trace DOM insertion, custom icons, callbacks, and error display.
- Run 3,093 independent runtime cases and parse their SVG structure and decoded attributes.
- Probe malformed input, nesting, compact expansion, memory use, and extreme dimensions in bounded child processes.
- Exercise the actual wrapper against reproduced resource cases.
- Render the example and inspect desktop and mobile browser layouts.

The runtime cases render 2,971 outputs and reject 122 inputs.
The structural checks find no unexpected scripts, event attributes, active schemes, unsafe CSS, or prototype changes.
They do not execute every hostile output in every browser.

The source audit also checks data-to-code paths and network-loading behavior.
It finds no author-controlled `eval`, `Function`, string timer, or remote code-fetch path in the runtime source.
These checks do not establish the absence of every vulnerability.

## Findings

### 1. High advisory in upstream development tools; excluded from this integration

**Rule:** dependency advisory review.

**Evidence:** the upstream lockfile includes `jison` / `jison-lex` → `nomnom` → `underscore@1.1.7`.
One underlying advisory produces four high-severity entries in the full development audit.
[GHSA-qpx9-hpmf-5gmw](https://github.com/advisories/GHSA-qpx9-hpmf-5gmw) describes unbounded recursion that can cause denial of service.

**Locations:** [source lockfile](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/package-lock.json#L2160),
and [test parser tooling](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/tests/support/jison.ts#L3).

**Impact:** upstream test tooling may inherit the advisory's availability risk.
The audit does not establish an exploitable path through that test runner.

**Control:** Explain installs only the published runtime package.
The package has no runtime dependencies, and its build does not bundle these test tools.
The integration's production dependency audit reports zero vulnerabilities.
No upstream dependency is changed or downgraded.

### 2. Medium availability risk from synchronous rendering; mitigated locally

**Rule:** resource exhaustion and bounded execution.

**Locations:** [render and output check](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/core.ts#L117),
[Venn layout](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/diagrams/venn/layout.ts#L24),
and [block expansion](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/diagrams/block/db.ts#L228).

**Evidence:** an 18,596-unit Venn input takes about 2.29 seconds in a raw runtime probe.
A larger input, still below Pele's source default, exhausts an isolated 192 MiB old-space heap.
A 33-unit block input returns a 707-unit SVG with a height of 1,200,004 pixels.
A 6,406-unit flowchart produces 1,757,343 SVG units through identifier amplification.

**Impact:** direct rendering of untrusted source can stall a UI or exhaust resources before an output-size check runs.
Extreme dimensions can also burden raster conversion.

**Classification:** confirmed residual resource behavior under a documented host responsibility.
It is not a demonstrated bypass of Pele's advertised source or edge limits.
The `maxEdges` option covers flowchart and agentflow, rather than all diagram types.

**Control:** Explain accepts text only and renders it in a disposable worker.
It limits source to 20,000 UTF-16 units and 80,000 UTF-8 bytes.
It sets a 500-edge cap and a 1,000,000-unit SVG cap.
It enforces a two-second default deadline and requests a 128 MiB old-generation heap limit.
It rejects nonfinite dimensions, sides above 16,384 pixels, and areas above 16 million pixels.

The actual wrapper rejects all three reproduced resource cases and returns control.
The worker's heap setting does not cap every native allocation or create an operating-system sandbox.
Parent Node.js heap flags can override that setting. The deadline remains necessary.
Keep local render calls serial. A public service needs separate authentication, concurrency limits, and rate limits.

### 3. Medium conditional SVG injection through host icon markup; feature omitted

**Rules:** JS-XSS-001 and JS-XSS-004.

**Locations:** [icon insertion](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/svg/builder.ts#L70),
and [DOM mount](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/mount.ts#L173).

**Evidence:** a host icon resolver can return raw markup with an SVG event attribute.
The published bundle preserves that attribute in its output.
The probe confirms active markup emission; it does not observe browser execution.

**Impact:** an application that lets attackers supply icon markup can create an SVG injection path.
This is a documented trusted-input boundary, rather than a diagram-source exploit.

**Control:** Explain supplies no icon resolver and accepts no arbitrary render options.
Its example displays a PNG and offers the exported SVG as a separate download.
Do not expose icon markup without a separate review.

### 4. Low network and navigation exposure in default rendering; disabled

**Rule:** JS-URL-002.

**Locations:** [URL defaults](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/util/url.ts#L77),
and [flowchart images](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/src/diagrams/flowchart/render.ts#L240).

**Evidence:** default HTTP/HTTPS images can issue requests when a viewer displays the diagram.
Relative URLs and ordinary navigation links are also supported functionality.

**Impact:** an untrusted diagram can contact an unwanted endpoint or send viewers to an author-selected link.
No unsafe-scheme bypass is confirmed by the URL probes.

**Control:** Explain fixes `links: false` and `images: false` outside source configuration.
It also requires an empty returned link collection.
All 200 disabled-link and disabled-image variants pass these checks.
Source directives cannot re-enable these owned settings in the tested paths.

### 5. Low local CLI availability issue; fixed

**Rule:** bounded file input.

**Location:** [bounded reader](../skills/explain/scripts/diagrams/render.mjs).

The first implementation opens input before checking whether its handle represents a regular file.
A FIFO without a writer can block that open before the worker deadline applies.

The reader now uses a nonblocking open and then rejects nonregular handles.
A regression test supplies a FIFO without a writer and confirms rejection within its process deadline.
The reader also checks file growth and rejects invalid UTF-8.
Output creation uses `wx` to preserve existing files and reject pre-existing output links.

### 6. Low future release hardening opportunity; exact artifact verified

**Rule:** JS-SUPPLY-001.

**Location:** [upstream release workflow](https://github.com/obsidianmd/pele/blob/659c3593ce43794dce7ec7ab45d424ad2de182a5/.github/workflows/release.yml#L18).

The upstream release workflow uses mutable action version tags.
Immutable reviewed action commits would reduce future release risk.
This review finds no evidence of compromise in the audited artifact.
Explain's exact version and integrity pin prevent a silent dependency update.

## Integration and verification

The [diagram guide](../skills/explain/references/diagrams.md) documents installation, limits, and compatibility.
The [renderer](../skills/explain/scripts/diagrams/render.mjs) runs independently from unrelated artifact dependencies.
The [example](../examples/pele-diagram/index.html) includes a compact PNG, SVG exports, and editable source.
Its raster exporter resolves theme variables and checks explicit fonts before replacing the assets.
The validation workflow runs the renderer tests, font-failure regression tests, and dependency audits.

The local regression suite covers accessible output, repeatability, mobile layout, injection, and disabled external resources.
It also covers source, edge, output and dimension limits, worker termination, UTF-8 validation, FIFO rejection, and output preservation.

Reproduce the integration checks:

```sh
npm ci --ignore-scripts --prefix skills/explain/scripts/diagrams
npm test --prefix skills/explain/scripts/diagrams
npm audit --omit=dev --prefix skills/explain/scripts/diagrams
python3 scripts/validate.py
python3 scripts/evaluate.py validate
python3 -m unittest discover -s evals -p 'test_*.py' -v
```

The final task evidence records actual command results and installed-file hashes.
An independent forward test also produces editable browser/cache/database diagrams at desktop and mobile sizes.
Its visual review finds readable labels and arrows without clipping after simplifying an initially wide mobile diagram.
The guide now states that `maxWidth` is a layout target rather than a hard ceiling.
Full local evidence lives in the task's `output/security/pele-2026-10-18` folder.
It includes the signature checks, reproduced build hashes, injection probes, and bounded resource probes.

No public upload endpoint, production deployment, or vulnerability disclosure forms part of this integration.
The review does not establish maintainer account security or the safety of future versions.
Recheck provenance, advisories, and regression tests before changing the version.
